### What the PRD's "Challenge deliverables checklist" gets wrong or leaves out

1. **Registration is under-specified.** The PRD says only "registered with every teammate listed". Registration needs a non-school email, 9-digit ZIPs for home and school, and a parent or guardian's name and email for each member (every builder is a minor). There is also an eligibility-quiz gate before the application unlocks. **Register this week**, not at submit time.
2. **The video spec is missing two details and its outline is in the wrong order.**
   - The purpose must be stated in *one clear sentence*.
   - The host must be YouTube or Vimeo, set to public.
   - The PRD's cut (story → numbers → competitors → demo → results → stack) buries the required items (names, app name, purpose, audience) and has **no code explanation**. The sample rubric gives 5 of 30 points to "Code". Open with the required items, then demo, then about 30 s on the architecture and one piece of core logic (for example, how the rules engine decides exemptions), then results. Cut "competitors" to one line.
   - 3:00 is a hard ceiling, and the PRD's "2–3 min" target is fine.
3. **Written answers.** Match the six official prompts. "Next steps" should be framed as "what would you change in a 2.0 version", and "technical challenges" must include *how you addressed it*.
4. **The AI disclosure needs more than the PRD plans.**
   - It must cover *all* AI usage, so keep a running log from day one. This project is being built with coding agents, and a vague disclosure written at the end is the highest disqualification-style risk in the checklist.
   - It must also show "significant individual contributions and technical understanding". Be ready to explain any file on request, because judges may ask for the source code.
5. **Missing: a third-party dependency list.** The originality rule requires documenting every library, framework and external tool (Next.js, Supabase, Twilio, react-pdf, the QR library, next-intl, any starter template, fonts). Put it in the README and in the submission.
6. **"Clean GitHub repo" is not a requirement. The real requirement is being able to produce the app and source on request**, with disqualification if you can't. The live app must keep working through **Jan 15, 2027** (see the Supabase pausing risk in B2). Provide a demo account seeded with fake data, never real pilot users' data.
7. **Missing: the Exit Questionnaire.** Each member must complete it after Oct 26.
8. **Missing: the privacy rule.** The rules forbid violating third parties' privacy rights. Blur or omit real users' hours, names and phone numbers in the video and screenshots, and use demo data. The PRD already plans signed releases for anyone filmed, and that plan is correct.

## PRD changes recommended

1. **Stack table:** change "Next.js 15" to **Next.js 16**. Add "Node ≥ 20.9 (project-local shim on the dev Mac)".
2. **SMS:** split it into two lines.
   - **Sign-in OTP: Supabase + Twilio Verify.** No 10DLC needed, about $0.058 per sign-in.
   - **Alerts and SMS replies: need an approved A2P 10DLC Sole Proprietor campaign**, registered by a parent or guardian or by the partner organization, submitted by Sep 29, with a 1–3+ week review.
   - Until the campaign is approved, alerts are **in-app** (plus optional Web Push, which works on iOS 16.4+ only when the app is installed to the home screen).
   - Remove "Works on flip phones" as a reason, and remove the Twilio "STOP handled" claim until the campaign exists.
3. **Scope fix:** supervisor confirmation is part of **P0 ShiftCred**, but both of its channels (kitchen dashboard, SMS reply) are **P1**. Promote a minimal "pending shifts → Confirm/Reject" supervisor screen to P0. Drop "reply Y" from the pilot.
4. **QR:** replace `@zxing/browser` with **`qr-scanner`**, dynamically imported on the scan route. It uses native BarcodeDetector on Android Chrome and falls back to a worker on iOS.
5. **PDF:** keep server-side `@react-pdf/renderer`, but **save to Supabase Storage and return a signed URL** (Vercel's 4.5 MB response cap). Compress photos on the client. Use TTF fonts, not WOFF2. Never ship react-pdf to the client.
6. **Hosting and ops:** add a Supabase keep-alive, or Pro for Nov–Jan, so the app works when judges ask for it (the embargo lifts Jan 15, 2027). Add a demo account seeded with fake data for judges and the video.
7. **Challenge deliverables checklist:** replace it with this list.
   - Register now: non-school email, 9-digit ZIPs, parent/guardian contact, eligibility quiz.
   - Video: 1–3 min, **public on YouTube or Vimeo**, opening with names, app name, **one-sentence purpose tied to the CA-16 benefits theme**, audience, and tools/languages; demo; **30 s code/architecture explanation**; results.
   - Answers to the **six** official prompts.
   - **Full AI-use disclosure** from a running log, plus a **list of every open-source library, framework and tool**.
   - Source code and live app producible on request through judging.
   - **Every member completes the Exit Questionnaire** after Oct 26.
8. **Video and privacy:** no real pilot users' names, phones or hours on screen (the rules protect third-party privacy); use the demo account. Signed releases for anyone filmed, as already planned.
9. **Performance budget:** say how the 200 KB is measured (Lighthouse or bundle analyzer on `/`), since Next 16's build output no longer reports First Load JS.
10. **Risks table:** add "SMS registration not approved by Oct 13" (mitigation: OTP via Verify, in-app confirmation and alerts). Add "Supabase project pauses during judging" (mitigation: keep-alive or Pro).
